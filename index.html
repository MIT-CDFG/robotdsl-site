MobileDSL 1.0 Guide

Domain-specific languages that compile into working robots

RobotDSL is a family of languages for robot development. One program describes the robot, its world, its behavior and how it is evaluated; a compiler assembles the machine, derives its settings and checks the whole system before anything runs. MobileDSL, for mobile robots, is the first language of the family.

Language

One program, four modules

MobileDSL folds the robot, its world, its behavior and its checks into one program; shared names keep them consistent.

CoreDSL The robot
Reusable components (chassis, wheels, sensors, attachments) joined through mating connectors.
WorldDSL The environment
Obstacles, the initial pose and named goals such as @world/door.
TaskDSL The behavior
A tree of navigation actions that refers to the world's goals by name.
EvaluateDSL The checks
What is observed during a run and which bounds must hold.
Robot nav_bot {  Mecanum_four_wheel chassis(ref="silver"),  Mecanum wheel_lf(ref="red", glue="0.0976 0.095 -0.0443 0 1 0"),  Mecanum wheel_lb(ref="red", glue="-0.1124 0.095 -0.0443 0 1 0"),  Mecanum wheel_rf(ref="red", glue="0.0976 -0.095 -0.0443 0 -1 0"),  Mecanum wheel_rb(ref="red", glue="-0.1124 -0.095 -0.0443 0 -1 0"),  Lidar front_scan(ref="lidar", glue="0.11 -0.0001 -0.0043 0 0 -1"),  Arm top_arm(ref="arm", glue="-0.0073 -0.0001 -0.0043 0 0 -1")}
Agent

From a request to a runnable robot

MobileCopilot chooses components and writes a MobileDSL program. The compiler assembles the parts, generates their dependent settings and returns errors the agent can fix.

  1. You

    Request

    Text or a reference image

  2. Library search

    Retrieve parts

    Parts, geometry and connectors

  3. Coding agent

    Write the program

    Robot, world, task and checks

  4. Compiler

    Compile & check

    Assembly and validation

  5. ROS & Gazebo

    Run & inspect

    Simulation and supported hardware

Compiler errors return to the agent. Edit the program, then compile again.

  1. Missing destination

    The task refers to W2, which is undefined.

  2. Agent adds the goal

    W2 is added to WorldDSL.

  3. Ready to run

    Recompiled: 0 errors, 1 advisory.

Successful compilation emits robot and world models, controller and navigation settings, a behavior tree and an evaluation plan. In the benchmark, simulation runs after authoring and provides no repair feedback to the agent.

Benchmark

Fifty design tasks, three coding agents

Each agent tackles the same 50 requests with MobileDSL and by directly authoring ROS/Gazebo files, using the same library, execution environment and 1,800-second authoring budget.

More systems finish their programmed behavior. Execution success improves by 42–50 percentage points across all three agent configurations. With Codex / gpt-5.6-sol, that is 37 of 50 systems instead of 12, with about 12 times less agent-written code.

Success means completing the generated program in simulation; it does not independently establish that the design fulfills the original request. All failures remain in the denominator. Agents receive no simulation feedback during authoring.

System execution success, MobileDSL vs. ROS/Gazebo files:
Codex / gpt-5.6-sol: 74% vs. 24% · Codex / gpt-6-astra: 82% vs. 40% · Claude Code / claude-opus-4-8: 64% vs. 22%.
