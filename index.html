RobotDSL Team MobileDSL 1.0

Domain-specific languages that compile into working robots

RobotDSL is a family of languages for robot development. One program describes the robot, its world, its behavior and how it is evaluated; a compiler assembles the machine, derives its settings and checks the whole system before anything runs. MobileDSL, for mobile robots, is the first language of the family.

Language

One program, four modules

Mobile robot development is usually spread over separate descriptions of structure, environment, behavior and evaluation, and it is the developer who keeps them consistent. MobileDSL folds them into one program. Shared names connect the modules, so changing a goal updates both the generated task coordinates and its distance check.

CoreDSL

The robot

An assembly of reusable components with functional roles: chassis, wheels, sensors and attachments, joined through mating connectors.

WorldDSL

The environment

Obstacles, the initial pose and named goals such as @world/door.

TaskDSL

The behavior

A tree of navigation actions that refers to the world's goals by name.

EvaluateDSL

The checks

Which quantities are observed and which bounds must hold during a run.

CoreDSL — a mecanum robot with a lidar and an arm (paper, listing 1)
Robot nav_bot { Mecanum_four_wheel chassis(ref="silver"), Mecanum wheel_lf(ref="red", glue="0.0976 0.095 -0.0443 0 1 0"), Mecanum wheel_lb(ref="red", glue="-0.1124 0.095 -0.0443 0 1 0"), Mecanum wheel_rf(ref="red", glue="0.0976 -0.095 -0.0443 0 -1 0"), Mecanum wheel_rb(ref="red", glue="-0.1124 -0.095 -0.0443 0 -1 0"), Lidar front_scan(ref="lidar", glue="0.11 -0.0001 -0.0043 0 0 -1"), Arm top_arm(ref="arm", glue="-0.0073 -0.0001 -0.0043 0 0 -1") } // compiles to URDF, controller, Nav2 footprint, Gazebo world, behavior tree and checks
Agent

MobileCopilot uses the language and the compiler as tools

Given a request in words or an image, a coding agent retrieves components, writes a MobileDSL program and refines it with the compiler's feedback. The language and the compiler take on the integration work an agent would otherwise do file by file.

Request

A description of the robot, its world and its task, optionally with a reference image.

Retrieve

Candidate components from the library, matched to the request.

Author

The four MobileDSL modules, written and revised by the agent.

Compile

Assembly, dependent settings and cross-module checks; errors return to the agent.

Simulate

Gazebo and Nav2 run the program; runtime verdicts score the system.

Deploy

The same program on the physical robot.

steps carried out by the toolchain rather than the agent

Benchmark

Fifty design tasks, three coding agents

Each agent processes every request once with MobileDSL and once by authoring ROS/Gazebo files directly, under the same budget, with the same component library and the same execution environment.

Physical robots

From the compiled world to the corridor

The robot description and the training world are compiled from MobileDSL. A depth-only obstacle-avoidance policy trained in that simulation drives the physical robot without fine-tuning on the real camera. Each clip pairs a fixed camera in the corridor (left) with the robot's own RGB and depth streams (right) at 2× speed; depth is colored over 0.3–3.5 m, near in red, and black marks no return.

Beyond mobile robots

MobileDSL is the first member of the family. Manipulation and legged platforms are in design; the compiler's component model is built to be shared across them.

RobotDSL roadmap
CompleteMobileDSL 1.0: the four modules, the compiler, the component library and the benchmark examples behind the paper's results. The compiler will be offered as a hosted service; its sources are not public.
In developmentMobileCopilot Studio with your own API key (preview online); component uploads with review; “report issue” on generated designs.
OpenPublic discussions and issues for questions, shared designs, announcements and feedback.
PlannedA documentation site and simulation runs in the browser.
