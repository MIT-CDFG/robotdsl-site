Guide

What is MobileDSL?

MobileDSL is the first language in the RobotDSL family, designed for mobile robots. One program describes the robot, its environment, its behavior and the checks performed during a run.

Instead of maintaining those descriptions separately, the modules share names. The compiler uses them to assemble the robot, derive its settings and check the system before execution.

Get started in Studio

The public Studio lets you browse the component library and edit a design in your browser.

  1. Explore the Library. Find a chassis, wheels, sensors or attachments and inspect the available parts.
  2. Open the Editor. Read the robot definition and edit its components. On a phone, use the Library and Editor tabs to move between them.
  3. Read the other modules together. Follow the robot name into the world, then the world’s named goals into the task. Check that the evaluation describes what you want to observe.

Available today: the library and editors work in the public Studio. Build, Copilot, exports, uploads and design reports require the hosted service, which is still in development.

One program, four modules

CoreDSL — the robot

Choose reusable components and connect them through mating connectors. The definition describes the chassis, wheels, sensors and attachments as one assembly.

WorldDSL — the environment

Describe obstacles, the robot’s initial pose and named destinations. A goal such as @world/door can be referenced by the task instead of repeating its location.

TaskDSL — the behavior

Describe a tree of actions, such as planning a path and following it to a named goal. The task refers to the robot and world defined in the same program.

EvaluateDSL — the checks

Specify what to observe during execution and which bounds must hold. These checks make the intended observations part of the program.

See the CoreDSL listing and interactive robot model.

Compile, check, then run

The compiler assembles the selected parts and checks the program’s references and constraints. Successful compilation emits robot and world models, controller and navigation settings, a behavior tree and an evaluation plan for ROS and Gazebo.

Compilation and execution answer different questions. A program can compile and still fail during a run; a completed run also needs to be checked against the original request.

Follow an error back to its definition

In the paper’s warehouse example, the task refers to a destination named W2 that the world does not define. Adding the missing goal in WorldDSL resolves the error; recompilation reports zero errors and one advisory.

Where MobileCopilot fits

MobileCopilot takes a text request or reference image, retrieves components and writes the MobileDSL program. Compiler diagnostics return to the agent so it can edit and recompile.

In the reported benchmark, simulation runs after authoring. The agent receives compiler feedback, but no simulation feedback during the design process.
