Vocabulary ​

This page is generated from mobiledsl.semantic.model.vocabulary; edit the code, not the page. It lists every name a program may use beyond the grammar's keywords, and what each takes. Numbers carry no unit: the parameter name carries it by suffix (_s seconds, _m metres, _rad radians, _mps metres per second).

Component types (.core) ​

A component type is the kind of part a program places. A part can be used as a type when its library entry lists the type under profiles; the type's category is the kind of physical thing the part must be, which decides what its entry declares (a wheel its radius, a chassis its connectors). The chassis takes only ref; every other component is placed by glue. A type exists only when the compiler acts on it: a chassis type has kinematics, a wheel type a contact model, a sensor type a simulated sensor and a use for its data. Everything the compiler merely carries is an Attachment; the library entry says what the part is.

Chassis types ​

What each chassis type needs and what the assembled base can do. A program places one wheel of an allowed type on each wheel mount; the wheel's glue must equal the chassis connector that the part's profile maps the mount to. A Caster wheel is passive and may sit on any other connector. Every mount is driven unless the table lists the driven ones; a mount that steers turns about the kingpin the chassis part declares on that connector.
