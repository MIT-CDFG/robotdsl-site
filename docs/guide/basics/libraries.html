Component libraries ​

Every ref in a program names a part in a component library. A library is a plain directory the compiler reads with --library; there is no install step and no default location.

sh
mobiledsl compile robot.core robot.world robot.task --library path/to/library --check

What is inside ​

text
<library>/
├── library.yaml                 the library's name and the ids of its parts
└── parts/<part-id>/
    ├── component.yaml           the part: shape, mass, mating points, what it can be used as
    └── assets/                  the mesh the part is drawn with

A part the library.yaml does not list does not exist to the compiler. Each part's component.yaml states:

  • its category: chassis, wheel, sensor or attachment;
  • its visual mesh, and a collision box that stands in for it;
  • its mass, centre of mass and inertia, with where the numbers came from;
  • its connectors, the named points where it mates with other parts;
  • its profiles, the component types it can be used as, such as Lidar or Diff_two_caster.

The library format specifies every field.

How a part is picked ​

Lidar top_lidar(ref = "lidar_ld06", ...) asks for the part lidar_ld06. The compiler checks that:

  • exactly one of the given libraries has a part with that id;
  • the part's category fits the component type, a sensor for Lidar;
  • the part lists the type under its profiles.

Each failure is its own diagnostic at the component.

Several libraries ​

Repeat --library to use several. A part must be in exactly one of them, so a library you keep next to your program can add parts to a shared catalog but not shadow one of its parts.

sh
mobiledsl compile robot.core robot.world robot.task \
  --library path/to/catalog --library my_parts --check

Incomplete parts ​

A shared catalog may hold a few parts that are not fully declared. Such a part is left out with a warning, and the rest of the library still serves every program that uses its complete parts. A program that names the part gets an error that says why it could not be loaded.

Meshes in the output ​

The compiler never opens a mesh; it copies each part's visual mesh into the output directory for the simulator to draw.
