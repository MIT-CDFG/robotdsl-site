Reading diagnostics ​

When something is wrong, the compiler says what, where and what to change, in the layout rustc and ruff use.

text
error[name.unknown_reference]: Navigate.goal: nothing named 'gaol' matches @world/<goal or entity>
  --> demo.task:3:25
  |
3 |         Navigate(goal = @world/gaol)
  |                         ^^^^^^^^^^^ not declared
  |
  = help: did you mean 'goal'?
PartSays
error[name.unknown_reference]The level and the code. The code is stable; tools and tests match on it.
The messageThe cause, in one sentence.
--> demo.task:3:25The file, line and column of the cause.
The excerptThe source line, with the exact bytes underlined.
= help:What to change.
= note:The facts the decision rested on.

The cause can be in a library as well as in the program: a problem with a part points into its component.yaml.

Errors and warnings ​

An error blocks: nothing is written. A warning does not. A validation rule that cannot decide, usually because a part does not state something, is a warning that says so:

text
warning[validation.assembly.footprint_known]: cannot decide: part 'imu_basic' of 'imu' declares no collision box, so the footprint may be larger than the known shapes
   --> demo.core:12:5
   |
12 |     IMU imu(ref = "imu_basic", glue = (0, 0.0001, 0.0344, 0, 0, -1))
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ no collision shape
   |
   = help: add a `collision` box to the part's component.yaml
   = note: evidence: x in [-0.177, 0.177] m, y in [-0.173, 0.173] m from chassis, wheel_lf, wheel_lb, wheel_rf, wheel_rb

Checked demo.core demo.world demo.task (9 checks, 1 undecided)

--warnings-as-errors makes every warning block, and each one says so in a note.

Everything at once ​

The parser stops at the first syntax error. Every later phase checks the whole program and reports every problem it finds, so one compile shows everything it can:

text
error[validation.assembly.wheel_mounts_filled]: a Mecanum_four_wheel chassis needs a wheel on 'front_left_wheel'; none is placed there
  --> demo.core:5:5
  |
5 |     Mecanum_four_wheel chassis(ref = "tslot_1515_drone")
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ no wheel on 'front_left_wheel'
  |
  = help: add a wheel with glue = (0.1275, 0.1494, -0.0216, 0, 1, 0)
  = note: evidence: 3 rolling wheels for 4 mounts

error[validation.assembly.glue_on_connector]: the glue of 'wheel_lf' matches no connector of the chassis; the nearest is 'wheel_mount_front_left', 0.008 m away with direction cosine 1.00
  ...

error: 2 errors; demo.core demo.world demo.task did not compile

One misplaced wheel produced both: the glue matches no connector, so the mount it was meant for is empty.

For tools ​

--json writes the whole result to stdout: every diagnostic, every validation rule with its status and evidence, and the files written. --color never turns colour off; it is also off when NO_COLOR is set or the output is not a terminal.

Exit statusMeans
0Nothing blocked; warnings may have been printed
1A diagnostic blocked
2The command line itself was wrong

Diagnostics in the reference specifies every field and code.
