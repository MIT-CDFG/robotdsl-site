The robot ​

The .core file declares one robot: a chassis, and the parts placed on it.

robotdsl
Robot diff_bot {
    intent "Two-wheel differential base with a rear caster and a top lidar"

    Diff_two_caster chassis(ref = "diff_base")
    Standard wheel_l(ref = "standard_80", glue = (0, 0.12, -0.02, 0, 1, 0))
    Standard wheel_r(ref = "standard_80", glue = (0, -0.12, -0.02, 0, -1, 0))
    Caster ball(ref = "caster_ball", glue = (-0.15, 0, -0.035, 0, 0, -1))
    Lidar top_lidar(ref = "lidar_ld06", glue = (0, 0, 0.05, 0, 0, 1))
}

Each line is a component: its type, its name, and its arguments. intent is an optional sentence for people and for the tools that generate programs.

The chassis ​

Exactly one component is the chassis. Its type says how the robot drives, and its ref names the chassis part in a library:

robotdsl
Diff_two_caster chassis(ref = "diff_base")

The chassis type decides which wheel mounts must be filled and what the base can do:

Chassis typeWheelsCan spin in placeHolonomic
Diff_two_castertwo Standard, plus a casteryesno
Diff_drivefour Standard, skid steeryesno
Mecanum_four_wheelfour Mecanumyesyes
Omni_drivefour Omni_wheelyesyes
Omni_three_wheelthree Omni_wheelyesyes
Tricycleone steered driven front wheel, two free rear wheelsnono
Ackermanntwo steered front wheels, two driven rear wheelsnono

Drive types says what the compiler emits for each.

Parts and glue ​

Every other component is a part placed by glue: the point and the direction of one of the chassis' connectors, in the chassis frame.

robotdsl
Standard wheel_l(ref = "standard_80", glue = (0, 0.12, -0.02, 0, 1, 0))
//                                            x   y     z     nx ny nz

The chassis part declares its connectors, and the glue must match one of them within 1 mm and 0.01 in direction. The part's own connector is then mated to it, the two directions facing each other. A seventh number, (x, y, z, nx, ny, nz, roll), turns the part about the direction.

You do not have to look the values up. A glue that matches no connector is reported with the nearest one and the exact glue to write:

text
error[validation.assembly.glue_on_connector]: the glue of 'wheel_lf' matches no connector of the chassis; the nearest is 'wheel_mount_front_left', 0.008 m away with direction cosine 1.00
  --> demo.core:7:52
  |
7 |     Mecanum wheel_lf(ref = "mecanum_black", glue = (0.12, 0.1494, -0.0216, 0, 1, 0))
  |                                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ matches no chassis connector
  |
  = help: to mount on 'wheel_mount_front_left' write glue = (0.1275, 0.1494, -0.0216, 0, 1, 0)
  = help: the chassis connectors are: front_mount, top_mount, wheel_mount_front_left, wheel_mount_front_right, wheel_mount_rear_left, wheel_mount_rear_right

A connector holds one part. Every wheel mount of the chassis type needs one wheel of the right type; a Caster is passive and may sit on any other connector.

Component types ​

KindTypes
WheelsStandard, Mecanum, Omni_wheel, Caster
SensorsLidar, Lidar3D, Camera, DepthCamera, RGBD, IMU, Ultrasonic, Range, Bumper
OtherAttachment: an arm, a gripper, a tray; it adds mass and shape, and the compiler does nothing else with it

A part can be used as a type when its library entry lists that type. The vocabulary lists every type with what it means.

Names ​

Component names are how the task and the evaluation refer to parts: @core/wheel_l. Two components cannot share a name, and the names of the links the targets add are reserved: base_footprint, base_link, <link>_contact_<n> for a ground contact a part declares, and <wheel>_steer for a steered wheel's knuckle.
